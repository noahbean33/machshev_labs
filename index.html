adjacent_channel_rejection.py 
from kestrel import studio, bench, limits

# 1. Model the channel once.
scene = studio.Scene(terrain="urban_canyon_v4")
scene.add_emitter("interferer", f0=3.86e9, power=-30)
link  = scene.link("gnb", "ue", bandwidth=100e6)

# 2. Define the measurement once.
test = bench.Sweep(
    stimulus=link.waveform("nr_ul_64qam"),
    sweep=range(-95, -55, 5),          # dBm
    measure=["evm", "aclr", "sensitivity"],
    limit=limits.from_spec("3GPP-38.101-1"),
)

# 3. Run it in CI, then on the rack. Same call.
sim = test.run(target=studio.simulator())
hw  = test.run(target=bench.rack("chamber-2"))

print(sim.diff(hw, tolerance="1.5 dB"))

How teams use it

From a whiteboard scenario to a signed report

The loop most of our customers settle into within their first quarter — simulation catches the design errors, hardware confirms the ones that matter.

STEP 01

Build the scenario

Import terrain and platform trajectories, place emitters and antennas, and solve propagation across the mission timeline.

STEP 02

Sweep it in CI

Every commit runs the regression suite against the simulator. Broken link budgets fail the build, not the schedule.

STEP 03

Play it into hardware

Range streams the same scenario through your front end at full rate, with calibrated delay, Doppler, and angle of arrival.

STEP 04

Diff and sign off

Compare simulated and measured results point by point, then export a versioned report with the full calibration chain attached.
